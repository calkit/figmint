# What figmint can vouch for

This page is a probe, not part of the paper. It points figmint's provenance
panel at the artifacts this project produces and reports what can actually be
established about each one — computed from the files on disk when the document
builds, not asserted here.

## A figure the pipeline produces

`figures/isotopes.png` is written by `src/plot.py` from `results/isotope_models.csv`
under a Snakemake rule, from a decision set recorded in `astra.yaml`.

:::{figmint} figures/isotopes.png
:width: 90%

Isotope model estimates by species.
:::

**Reproducible** — figmint reads the `Snakefile` and finds the rule declaring
this exact path as an output. That is a claim something can check without running
anything, which is what separates `reproducible` from a sidecar asserting the
same thing.

Worth saying what figmint does *not* do here. It does not execute Snakemake,
resolve wildcards against the filesystem, or evaluate the Python in the workflow.
It reads declarations. A rule whose output is built by an expression is not
matched, and the artifact falls back to whatever other evidence it carries —
being unable to prove a claim is not the same as disproving it.

Nor can it say whether the rule is *current*. Calkit projects get that from
`dvc.lock`, which records every dependency's hash as of the last run; Snakemake
keeps no comparable record, so freshness here is unknown rather than false.

## An image nobody computed

`schematic.png` was generated by a model. Nothing in the pipeline produces it; it
was made once and committed.

:::{figmint} schematic.png
:width: 60%

Measurement schematic for culmen and flipper dimensions.
:::

**Signed** — valid C2PA Content Credentials naming `gpt-image 2.0`,
cryptographically bound to the bytes, disclosing that it is machine-generated.
figmint surfaces that disclosure in the document rather than leaving it in the
file where only a specialised tool would find it.

That is a different guarantee from the figure above, not a stronger one. Signing
answers *who made this, and has it been altered*; a pipeline rule answers *can I
make it again*. For a research figure the second is usually what matters.

## Where the chain actually stops

`penguins.csv` is the raw data. No rule produces it — `download.py` fetches it,
and that script is run by hand.

:::{figmint} penguins.csv
:::

**Unidentified**, and this is the real finding. Everything downstream is
reproducible, and the whole edifice rests on a CSV that, as far as any automated
check can tell, appeared one day.

The information exists: `download.py` documents three DOIs on the Environmental
Data Initiative, one per species, and cites Gorman et al. But it is in a module
docstring — the right place for a reader and no place at all for a checker. One
command moves it somewhere a checker can reach:

```sh
figmint import penguins.csv \
    --doi 10.6073/pasta/abc50eed9138b75f54eaada0841b9b86 \
    --citation 'Gorman KB, Williams TD, Fraser WR (2014) PLoS ONE 9(3):e90081' \
    --from 'Palmer Station Antarctica LTER, via the EDI PASTA API'
```

## What this example is for

The turbine example next door uses Calkit and composes its figures in draw.io.
This one uses Snakemake and writes PNGs straight from matplotlib. Neither is
figmint's own format, and both should get honest answers.

Before figmint could read a `Snakefile`, this page said something false: every
figure came out `unidentified`, and the AI-generated schematic was the
best-identified artifact in a carefully reproducible analysis. That inversion was
never a measurement of this project's rigour — it was a measurement of which file
formats figmint could parse, wearing the costume of one.
