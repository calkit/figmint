# Cross-flow turbine performance

This document is a playground for the editing loop: a figure you can open in
draw.io, edit, and save, while figmint keeps track of where each panel came from
and tells you when one has gone stale.

```{code-cell} python
:tags: [remove-cell]

# The analysis result, loaded once so prose anywhere in the document can quote
# it. Nothing here is a literal: every number below comes from the pipeline.
import json
peak = json.load(open("results/peak.json"))
```

Left: power coefficient against tip speed ratio, generated by

As [](#fig-performance) shows, the power coefficient peaks near a tip speed
ratio of {eval}`round(peak["lambda_star"], 2)` — a number read from the
pipeline's own output rather than typed here. It used to say 2.8, which
disagreed with the 2.71 the figure showed; both were reproducible, and nothing
could see the contradiction. [](#astra) is about why.

The two panels have very different standing, which is the point of the example.
The plot is a pipeline output: `calkit.yaml` says which stage made it, so it can
be remade. The schematic came from a model, and the only reason anyone knows
that is the Content Credentials embedded in the PNG.

## A figure that had to leave the document

This one used to be computed inline, in a `{code-cell}` that read the CSV and
fitted a quartic while the document built. That is a legitimate third mode, and
for a while it was the best one here: the code was visible to the reader, and
`myst build --execute` remade it every time. No provenance tracking needed,
because there was no provenance problem to solve.

It stopped being adequate the moment the polynomial degree turned out to matter.
An inline literal cannot be swept: there is nowhere for a universe to put a
different value, and nothing downstream can record which value was used. So the
fit moved into a pipeline stage, and the figure became an artifact:

```{figure} figures/cp_fit.svg
:name: fig-fit
:width: 80%

The fit and the located peak, produced by the `fit-peak` pipeline stage under
the decisions in `params/universe.yaml`. Change a decision and this figure, the
metric, and every number quoted in the prose move together.
```

The peak is at $\lambda^* \approx$ {eval}`round(peak["lambda_star"], 2)`, read out
of the fit in [](#fig-fit) rather than typed in — so the number in the prose
cannot drift away from the figure beside it.

That was always true of *this* number. What was not true is that the fit behind
it was one defensible choice among several, made silently.

The document still quotes the result inline — the numbers above come from
`results/peak.json`, not from anything typed here — but the *computation* now
lives where a decision can reach it.

That is the general shape of the trade. A figure computed by the document is the
cheapest kind to trust, right up until one of its choices becomes consequential.
Then it needs to be an artifact, because a decision that cannot be varied is not
a decision at all: it is a literal that nobody has noticed yet.

figmint exists for the cases neither mode reaches. A hand-arranged composite, a
micrograph, a schematic drawn in draw.io, a panel from a collaborator — none of
those can be regenerated by a code cell or a pipeline stage, which is exactly why
something has to record where they came from.

## The document's own provenance

A published document is a composite in the same sense a figure is: several
artifacts, each with its own chain, several stages deep. `figmint-provenance`
says so for the whole page rather than one figure:

:::{figmint-provenance}
:table: true
:graph: true
:::

The chain runs `data/performance.csv` → `plot_cp.py` → `cp_curve.svg` →
`composite.drawio.svg` → this document, with the imported schematic joining at
the composite. Nothing in that path is asserted by hand: the pipeline stages come
from `calkit.yaml`, the freshness from `dvc.lock`, and the panel-level edges from
the diagram itself.

(astra)=
## The decisions behind the number

`astra.yaml` records the methodological choices this analysis makes, each with
its alternatives and the reasoning:

| Decision | Default | Range across options |
| --- | --- | --- |
| `fit_degree` | quartic | λ* 2.63 → 2.93, Cp* 0.302 → 0.399 |
| `peak_method` | argmax of the fit | λ* 2.70 → 2.80 |
| `tsr_min` | no cut | — |

Every one of those was a literal in a code cell before. The polynomial degree
alone moves peak Cp by 32%, which is the number an engineer would quote.

ASTRA does not run anything, and it does not restate the pipeline. Each output's
recipe hands execution to `calkit run <stage>`; the only thing crossing the seam
is `params/universe.yaml`, written from a universe and declared as an input to
the `fit-peak` stage:

```sh
uv run python scripts/set_params.py \
    --fit-degree cubic --peak-method fit_grid_argmax --tsr-min no_cut
calkit run          # re-runs fit-peak and everything downstream, nothing else
```

`calkit.yaml` never mentions ASTRA, and `astra.yaml` never restates a stage.
Either file still stands on its own — the same boundary figmint draws when it
references a Calkit stage rather than defining one.

## What makes this different from a normal figure

Two files, with a firm rule about which is which:

| File | Role |
| --- | --- |
| `figures/composite.drawio` | **Source.** You edit this in draw.io. No stage writes it. |
| `figures/composite.drawio.svg` | **Derived.** The pipeline renders it. Never edit it. |

It is tempting to use one file for both, because a `.drawio.svg` genuinely is
viewable *and* editable — the whole diagram rides along in a `content` attribute.
But a file that is both the input and the output of a pipeline is a file
regenerated from itself, and the next run would silently overwrite whatever you
had drawn. DVC refuses to build that graph, correctly.

What the `--embed-diagram` export buys instead is that the *derived* file keeps
the provenance: each panel still carries `src` and `hash` naming the file it came
from and the exact version embedded, and the panel bytes are untouched, so
anything the original carried — Content Credentials included — survives into the
published picture. That is what lets the questions below be answered
mechanically, against the artifact a reader actually sees.

## The loop

### Open it for editing

```sh
make edit
```

Opens `figures/composite.drawio` — the source — in draw.io. Rearrange, restyle, add annotations, add
LaTeX — then save. The `src` and `hash` attributes survive, because draw.io
preserves custom shape data through a round-trip.

:::{warning}
Do **not** use draw.io's *Insert → Image* to add a figure. draw.io resizes
anything over 1200 px through a canvas, which destroys Content Credentials
outright — including the AI-generation disclosure on a generated image. Use
`make place FIGURE_IN=figures/whatever.svg` instead, which embeds the bytes
verbatim.
:::

### Ask whether anything is stale

```sh
make status
```

Three different questions, kept apart deliberately:

| Question | Answered by |
| --- | --- |
| Has a panel changed since it was embedded? | `figmint status` / `figmint reimport --check` |
| Is the panel's own *source* out of date? | `figmint check` — the rating drops |
| Is every panel identified well enough to publish? | `figmint check` |

The middle one is the subtle case. Edit `scripts/plot_cp.py` and change nothing
else: the embedded copy still matches `figures/cp_curve.svg` byte for byte, so
nothing is stale in the first sense. But `cp_curve.svg` is now the output of a
version of the script that no longer exists — `dvc.lock` records the hash the
script had when the stage last ran, and it no longer matches.

So the panel stops being `reproducible` and falls back to `generated`: something
names what produced it, but nothing can verify the claim until the pipeline runs
again. The preview says so in red, and points at `calkit run` rather than
`make refresh` — re-embedding would only copy the out-of-date file more faithfully.

### See it go stale

```sh
make break      # edits the data, reruns the plot
make status     # the embedded copy is now out of date
```

Nothing in draw.io can notice this on its own: the diagram holds a *copy* of the
panel, with no link back to the file. That is what `reimport` is for.

### Refresh and rebuild

```sh
make refresh    # re-embed the changed panel, re-render the picture
make site       # rebuild this document
```

Or `calkit run`, which does both in dependency order.

`make refresh` is two steps, not one: figmint re-embeds the changed panels into
`.build/composite.drawio`, then draw.io renders that to the published
`.drawio.svg`. figmint stops at the diagram because it can update the embedded
copy but not the picture drawn around it — and a file whose rendering and
metadata disagree is worse than one that was never written.

## Provenance, as recorded

```sh
make check
```

The project sets a floor in `figmint.toml`: every component must at least declare
where it came from. Both panels clear it, by different routes:

| Panel | Level | Why |
| --- | --- | --- |
| `figures/cp_curve.svg` | `reproducible` | `calkit.yaml` declares it as the output of the `plot-cp` stage |
| `figures/turbine.png` | `signed` | valid C2PA Content Credentials naming Google as the producer |

### The gap the ratings cannot see

`make check` also prints this:

```
WARN  input data/performance.csv has no stated origin
      no stage produces it and no `imported_from` in calkit.yaml explains it
```

Both components are identified. The plot is a verified pipeline output. And the
whole chain still rests on a CSV that appeared in the repository one day —
`calkit.yaml` gives it a `title` and a `description`, which say what it is, but
neither says where it came from or how anyone would get it again.

This is the failure the component ratings are structurally unable to catch,
because they all look at components and the gap is one link further back. It is
reported as a warning rather than a failure: nothing about the figure is wrong,
and failing the build here would penalise exactly the projects that bothered to
adopt a pipeline. Adding `imported_from` (a URL, a DOI, or another Calkit
project) closes it.

### Why the plot's rating is the more useful one

The plot's rating is the more useful one. `reproducible` is a claim that can be
*verified* without trusting anyone: the stage is written down, so the file can be
made again. `signed` answers a different question — who made this, and has it
been altered since — and here the answer is a model. The credentials record
`digitalSourceType: composite`, meaning AI-generated somewhere up the chain, so
the disclosure travels with the figure instead of living in someone's memory.

Getting it in that way mattered. The PNG is 1408 px wide, which is over draw.io's
1200 px canvas threshold: importing it through *Insert → Image* would have
re-encoded it, and the Content Credentials would have been gone without warning.
`figmint place` writes the original bytes, so the manifest survives all the way
into the rendered `.drawio.svg` — you can pull the panel back out of the
published file and still verify it.
