# Cross-flow turbine performance

This document is a playground for the editing loop: a figure you can open in
draw.io, edit, and save, while figmint keeps track of where each panel came from
and tells you when one has gone stale.

## The figure

:::{figure} figures/composite.drawio.svg
:name: fig-performance
:width: 90%

Power coefficient against tip speed ratio. The panel is generated by
`scripts/plot_cp.py` from `data/performance.csv`; figmint records that link
inside the diagram.
:::

As [](#fig-performance) shows, the power coefficient peaks near a tip speed
ratio of 2.8.

## What makes this different from a normal figure

`figures/composite.drawio.svg` is one file doing three jobs:

1. **The published picture.** MyST embeds it directly, above.
2. **The editable source.** The whole draw.io diagram is stored in a `content`
   attribute on the SVG, so opening this file in draw.io gives you the editor
   back — no separate `.drawio` to keep in sync.
3. **The provenance record.** Each imported panel carries `src` and `hash`
   attributes naming the file it came from and the exact version embedded.

That third one is what lets the questions below be answered mechanically.

## The loop

### Open it for editing

```sh
make edit
```

Opens the `.drawio.svg` in draw.io. Rearrange, restyle, add annotations, add
LaTeX — then save. The `src` and `hash` attributes survive, because draw.io
preserves custom shape data through a round-trip.

:::{warning}
Do **not** use draw.io's *Insert → Image* to add a figure. draw.io resizes
anything over 1200 px through a canvas, which destroys Content Credentials
outright — including the AI-generation disclosure on a generated image. Use
`make place FIGURE=figures/whatever.svg` instead, which embeds the bytes
verbatim.
:::

### Ask whether anything is stale

```sh
make status
```

Two different questions, kept apart deliberately:

| Question | Answered by |
| --- | --- |
| Has a panel changed since it was embedded? | `figmint status` / `figmint reimport --check` |
| Is every panel identified well enough to publish? | `figmint check` |

### See it go stale

```sh
make break      # edits the data, reruns the plot
make status     # the embedded copy is now out of date
```

Nothing in draw.io can notice this on its own: the diagram holds a *copy* of the
panel, with no link back to the file. That is what `reimport` is for.

### Refresh and rebuild

```sh
make refresh    # re-embed the changed panel, re-render the .drawio.svg
make site       # rebuild this document
```

`make refresh` is two steps, not one: figmint updates the embedded diagram and
writes it out as a plain `.drawio`, then draw.io re-renders the picture around
it. figmint will not write a `.drawio.svg` in place, because it can update the
diagram but not the rendering — and a file whose picture and metadata disagree is
worse than one that refuses to be written.

## Provenance, as recorded

```sh
make check
```

The project sets a floor in `figmint.toml`: every component must at least declare
where it came from. This panel does better than that — `calkit.yaml` declares it
as the output of the `plot-cp` stage, which is a claim that can be *verified*
rather than merely asserted, so figmint rates it `reproducible`.
